## 一、资质

### 1.1 版号:不需要,但要做前置备案

官方原文:

> 不涉及内购功能的小游戏**无需提交版号**,普通小游戏在正式上架前需完成**小游戏前置备案**,以满足上线前备案要求。

- 本项目无内购 → **不办版号**;
- 但**前置备案必须办**,漏这一步是很多教程没说的坑;
- 备案资料要求见后台「小游戏前置备案申报」入口。

### 1.2 未成年人防沉迷:平台托管,**不需要写任何代码**

| 情况 | 要求 | 本项目 |
| --- | --- | --- |
| 游玩方式**只有小游戏** | 防沉迷由平台托管,开发者无需额外操作 | ✅ **当前就是这个情况** |
| 同时提供 APK(含测试包) | 必须自己完善防沉迷,或接入 TapPlay | ⏸ 已暂缓,不触发 |

阶段内只发小游戏,所以实名窗、时长限制、宵禁**全部由 TapTap 平台接管**,你这边一行代码都不用写。

> 代码里 `TapAntiAddiction` 在小游戏环境(`isTapMini`)会直接置为可玩、**不重复校验** —— 这是故意的:
> 平台已经在计时,客户端再算一遍会造成**双重计时、把正常玩家误封**。
> 之前为 APK 写的 TapSDK 防沉迷桥接保留不动,不影响小游戏包(小游戏构建不编译 Java),将来发 APK 时直接启用。

### 1.3 其他

- 软著:有(`上架资料/软著.png`),按后台「小游戏资质」要求上传;
- 授权链:无 IP 无需提供。

## 二、包体

### 2.1 出包(与 APK 完全是两条链路)

1. 装 Cocos 官方插件 `tap-minigame-ts.zip`(当前 1.2.2)→ 扩展管理器导入 → 启用,控制台出现 `[Tap小游戏] 扩展已加载`;
2. 构建平台选 **微信小游戏** → 勾选 **转换为Tap小游戏** → 填 **Tap小游戏 AppID**;
3. 构建 → 产物 `build/TapBuild/game/`,**上传的是同级的 `game.zip`**。

> 项目现状:全局扩展只有 `cocos-service` / `funplay-cocos-mcp`,插件**还没装**;`build/` 下也还没有 `wechatgame` 目录,首次是全量构建。

### 2.2 包体硬指标

| 指标 | 要求 | 怎么验 |
| --- | --- | --- |
| 首包大小 | **≤60MB** | 看 `game.zip` 体积 |
| wasm 分包 | br >6MB 建议开,>10MB **必须**开 | 看产物里 `.br` 文件大小 |
| 版本号 | `V x.y.z`,每段整数,**唯一且递增**,不能与已上线/审核中重复 | 后台填写时校验 |
| TapTap 登录 | 包体内**必须已正确接入**,否则 TapTap 用户无法正常游玩 | 真机点登录能拉起 |

> Cocos 3.8 的普通 2D 包一般不会碰到 wasm 分包,转换后 `du -sh build/TapBuild/game` 看一眼就行。

### 2.3 登录怎么接(本项目无服务端)

官方要求"包体内必须已正确接入 TapTap 登录"。流程是 `tap.login()` → 拿临时 `code` → 服务端 `code2Session` 换 `openid`。

**本项目是单机游戏,没有服务端**,所以:

- 客户端调 `tap.login()` 拿到 `code` 就算"已接入"(平台校验的是接入动作,而不是你有没有服务端);
- `code` **只打日志、不上报**,不做 `code2Session`(也没有服务器可做);
- 将来要接云存档 / 排行榜 / 跨设备进度,才需要补服务端换 `openid`。

代码位置:`assets/script/tap/TapManager.ts` 的 `login()`,已兼容"回调式 / Promise 式"两种基础库;
启动时由 `WxMgr.init()` 自动触发一次。真机验证方式:看日志有没有 `[TapManager] 登录完成`,以及 TapTap 用户首次进入时是否被平台拦下要授权。

## 三、文字资料

| 字段 | 要求 | 注意 |
| --- | --- | --- |
| 游戏名称 | 与包名一致 | 美食餐厅爱消消 |
| 简短简介 | 一句话说清玩法 | 小游戏场景下玩家决策更依赖这一句 |
| 简介 | 3 段以内,**不要留空行** | 空行会导致 App 内显示异常 |
| 标语 + 标签 | 休闲 / 益智 / 消除 / 单机 | 标签错会影响推荐 |
| 更新日志 | **首发留空** | 填了会被当成版本更新 |

## 四、素材(与 APK 共用一套)

| 素材 | 尺寸/格式 | 必需 | 现有 | 结论 |
| --- | --- | --- | --- | --- |
| 图标 | 512×512 JPG/PNG | ✅ | `512.png` | ✅ 可用 |
| 详情页顶部图 | 1920×1080(关键内容 1760×920 内) | ✅ | 无 | ❌ 要新做 |
| 推广图 | 1920×1080 | 可选 | 无 | 可略 |
| 截图 | 同尺寸 ≥3 张;**小游戏强烈建议 9:16 竖版** | ✅ | 4 张 1206×2622 | ⚠️ 建议重截 1080×1920 |
| 视频 | MP4 ≤60 秒 | 可选 | 无 | 可略 |

> 小游戏玩家在 TapTap App 内竖屏浏览,竖版 9:16 截图比横版重要得多,**这是与小游戏转化率直接相关的一项**。

## 五、上架七步(顺序别调)

1. **创建游戏**:开发者中心 →「创建游戏」→ 游玩提供方式选「**小游戏**」→ 拿到唯一游戏 ID;
2. **上传包体**:「商店 → 小游戏管理 → 包体管理 → 上传包体」,传 `game.zip`,平台自动基础校验,通过后生成测试二维码;
3. **自测**:手机扫码连玩三局,标准是"没有明显卡顿、白屏、死路";
4. **补资料**:图标 / 截图 / 简介 / 标语 / 标签;
5. **资质**:「商店 → 小游戏管理 → 小游戏资质」上传软著 + 前置备案,并等资质审核通过;
6. **测试**:用测试计划让真实玩家先进来跑几轮(可选但推荐);
7. **提审 → 上线**:审核通过(首次 1–3 日)**≠ 上线**,要在「发布设置」里点上线;
   首次定时上线必须设在当前时间 **6 小时之后**,且**资质不支持定时**,要预留时间。

## 六、驳回高发点(按官方口径整理)

| 驳回原因 | 应对 |
| --- | --- |
| **打不开**(最常见) | 第一版就要解决,别指望先传上去再说 |
| 玩法同质化 / 纯复刻 | 要有原创机制;本项目是三消 + 连锁爆破,建议在简介里点明差异点 |
| 内容太短、无成长、大量空白界面 | 关卡进度、体力、星级、道具都要能体现 |
| 截图用过场动画而非实机画面 | 见第四节拍摄清单 |
| **有广告却没勾隐私政策/防沉迷声明** | 后台勾选,**不是**游戏内加页面 |
| 版本号重复 / 不是递增 | `V x.y.z` 每段整数 |

## 七、和小游戏 vs APK 的差异(别混)

| 项 | 小游戏(当前) | APK(暂缓) |
| --- | --- | --- |
| 产物 | `game.zip` | 已签名 `.apk` |
| 版号 | **不需要**(无内购) | ❓ 待确认,通常需要 |
| 前置备案 | **必须** | 不需要 |
| 防沉迷 | **平台托管,零代码** | 必须自接 TapSDK |
| 广告 | `tap.*` JS API | Dirichlet 原生 SDK(桥) |
| 资质入口 | 商店 → 小游戏管理 → 小游戏资质 | 商店 → 游戏资料 → 游戏资质 |
| 审核时长 | 首次 1–3 日 | 首次 1–3 日 |

| P2 | 20 秒玩法视频 | 提升转化,非必需 |

### 8.1 本阶段可以完全忽略的东西

只发小游戏时,下面这些**都不用碰**,别浪费时间:

- ❌ TapSDK / Dirichlet 的 AAR、`TapConfig.java`、keystore、ABI 裁剪 —— 全部属于 APK;
- ❌ 版号、ICP —— 小游戏无内购不需要;
- ❌ 自接防沉迷 —— 平台托管。

> 顺带一个好处:原生桥是**反射调用**,没放 AAR 也能编译;小游戏构建本来就不编译 Java。
> 也就是说现在直接出小游戏包,不会被 APK 那套东西卡住。
